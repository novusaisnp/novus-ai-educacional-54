│ Cargo do ERP → role do satélite (com sugestão auditável) + fecha gap de auditoria de privilégio                                                                                                │
│                                                                                                                                                                                                │
│ Contexto                                                                                                                                                                                       │
│                                                                                                                                                                                                │
│ Usuário levantou preocupação de arquitetura: cadastro de colaborador acontece no ERP (novusai-erp), mas hoje, quando esse colaborador vira usuário do satélite (novus-ai-educacional-54), a role (professor/coordenacao/secretario) é digitada do zero por quem faz o convite (equipe.tsx), sem nenhuma relação com a função real da pessoa já cadastrada no ERP (colaboradores.cargo_id → cargos.nome).                                                                                                                                                                                  │
│                                                                                                                                                                                                │
│ Investigação (2 agentes Explore, um por repo, código lido direto) confirmou 3 problemas reais, não hipotéticos:                                                                                │
│                                                                                                                                                                                                │
│ 1. colaborador-preflight esconde a função de propósito — a função do ERP já seleciona só id, ativo, deleted_at, data_demissao de colaboradores (novusai-erp/supabase/functions/colaborador-preflight/index.ts:102-107), com comentário explícito dizendo pra nunca expor cargo/função ao satélite. colaboradores.cargo_id (ligado a cargos.nome, RH real, 20260710180530...sql:76-136) existe e está populado, só não é usado.                                                                                                     │
│ 2. Zero auditoria de mudança de privilégio nos dois repos. ERP: historico_operacoes (tabela genérica pra isso) existe mas não tem nenhum caller — código morto (registrar_historico_operacao, sem uso em src/). Mudança de usuarios.perfil_id ou perfis_acesso.permissoes não fica registrada em lugar nenhum. Satélite: create-staff-user/switch_active_organization nunca chamam logAudit — atribuição de role no convite é invisível pra auditoria.                                                                                                                                     │
│ 3. Padrão de auditoria que já funciona existe, só não é usado aqui: tabelas historico_movimentacoes_bancarias/historico_estoque_movimentacoes no ERP são alimentadas por trigger (AFTER INSERT OR UPDATE OR DELETE, to_jsonb(OLD)/to_jsonb(NEW), automático, sem depender de código de app lembrar de chamar nada) — ver novusai-erp/supabase/migrations/20250708172303-f32181f1-7f25-40e7-8595-5e2381e3ca9a.sql:229-310 como referência funcional a copiar, em vez do padrão morto baseado em RPC.                     │
│                                                                                                                                                                                                │
│ Decisões já confirmadas com o usuário (via AskUserQuestion):                                                                                                                                   │
│ - Mapeamento cargo→role via campo categoria_padrao no cargo do ERP (não tabela de mapeamento por cargo individual) — mais simples, reusável por qualquer satélite futuro sem schema novo por integração.                                                                                                                                                                                    │
│ - Role sugerida pelo ERP é sugestão pré-preenchida, não trava — quem convida pode sobrescrever, mas toda escolha (aceitou ou sobrescreveu) fica auditada.                                      │
│ - Escopo desta fatia: só o fluxo cargo→role + fechar os 2 gaps de auditoria. Ativar de verdade o catálogo de ~70 permissões granulares do ERP (hoje só 1 de 70 é realmente has_permissao-checada, critica é decoração de UI sem nenhum enforcement) fica registrado como fatia 2 separada, não iniciada agora — ver seção "Fora de escopo" no final.                      │
│                                                                                                                                                                                                │
│ Abordagem                                                                                                                                                                                      │
│                                                                                                                                                                                                │
│ 1. ERP — cargos ganha categoria_padrao                                                                                                                                                         │
│                                                                                                                                                                                                │
│ Migration aditiva: cargos.categoria_padrao text NULL CHECK (categoria_padrao IN ('pedagogico','coordenacao_administrativa','administrativo','financeiro','diretoria','outro')). Nullable — cargos existentes ficam sem categoria até alguém preencher (sem migração de dado, decisão consciente: RH real deve escolher, não adivinhar). Adicionar Select de categoria no form real de cadastro/edição de cargo: src/components/modules/FormCargo/index.tsx (usa useCargos.ts→cargoService.ts createCargo/updateCargo — único ponto de escrita em cargos hoje).                       │
│                                                                                                                                                                                                │
│ Taxonomia genérica de propósito (não usa nomes de role do educacional) — mesmo princípio já documentado na skill erp-satellite-integration/memória feedback_satellite_generic_contracts: o ERP nunca deve saber o vocabulário de role de um satélite específico.                                                                                                                              │
│                                                                                                                                                                                                │
│ 2. ERP — colaborador-preflight passa a retornar categoria_padrao                                                                                                                               │
│                                                                                                                                                                                                │
│ novusai-erp/supabase/functions/colaborador-preflight/index.ts:102-107: adicionar cargos(categoria_padrao) ao select (join por cargo_id), incluir categoria_padrao: string | null no corpo de resposta (fora do preflightResponseSchema atual de autorizado/bloqueios — campo novo, aditivo, não quebra nenhum consumidor existente que ignora campos desconhecidos). Manter tudo mais como está (autorizado/bloqueios continuam a fonte de verdade pra bloquear ou não o convite).                                                                                                        │
│                                                                                                                                                                                                │
│ 3. Satélite — create-staff-user resolve sugestão + audita                                                                                                                                      │
│                                                                                                                                                                                                │
│ novus-ai-educacional-54/supabase/functions/create-staff-user/index.ts:                                                                                                                         │
│ - Ler categoria_padrao da resposta do preflight (já chamado em checkColaboradorValidado, linha ~56).                                                                                           │
│ - Novo mapeamento local (constante, não vem do ERP): CATEGORIA_TO_ROLE: Record<string, StaffRole | null> — ex. pedagogico→professor, coordenacao_administrativa→coordenacao, administrativo→secretario, financeiro→null, diretoria→null, outro→null (null = sem sugestão, ninguém deve auto-sugerir admin; diretoria/financeiro ficam sem sugestão automática por serem sensíveis — decisão a confirmar com usuário se ficar estranho na prática, mas fail-safe por padrão).                                                                                           │
│ - Body de resposta do endpoint ganha suggestedRole: string | null (a categoria resolvida vira role sugerida, ou null).                                                                         │
│ - Ao persistir o profile (linha ~199-206), gravar 2 colunas novas em profiles (migration aditiva): role_assigned_via text CHECK (IN ('erp_suggestion','manual_override','no_erp_suggestion')), erp_suggested_role text NULL.                                                                                                                                                                  │
│ - Chamar audit_logs insert direto (mesmo shape de logAudit(), mas replicado inline — logAudit() em si importa o client React, não dá pra chamar de dentro de uma edge function Deno; usar o adminClient já instanciado na function) registrando role final, erp_suggested_role, role_assigned_via, cpf, ator (quem convidou).                                                              │
│                                                                                                                                                                                                │
│ 4. Satélite — equipe.tsx pré-preenche e mostra a origem                                                                                                                                        │
│                                                                                                                                                                                                │
│ Depois que checkColaboradorValidado/preflight retornar (hoje só usado pra bloquear — passa a também trazer suggestedRole), o Select de role em equipe.tsx (~linha 196-203) nasce com o valor sugerido já selecionado (se houver) + um badge pequeno "sugerido pelo ERP (cargo: X)" ao lado — texto vem do categoria_padrao/cargo real, não hardcoded. Continua editável — trocar manualmente é o que grava role_assigned_via='manual_override'.                                                                                                                                 │
│                                                                                                                                                                                                │
│ 5. ERP — trigger de auditoria pra mudança de privilégio                                                                                                                                        │
│                                                                                                                                                                                                │
│ Duas tabelas novas, populadas por trigger (copiar o padrão de registrar_historico_movimentacao, não o padrão morto de historico_operacoes):                                                    │
│ - historico_colaboradores_cargo — trigger AFTER UPDATE OF cargo_id, departamento_id, setor_id ON colaboradores, grava colaborador_id, dados_anteriores, dados_novos, usuario_id (auth.uid()), created_at.                                                                                                                                                                                    │
│ - historico_usuarios_perfil — trigger AFTER UPDATE OF perfil_id ON usuarios (mudança de perfil de acesso) + AFTER INSERT OR UPDATE OR DELETE ON user_roles (mudança de role admin/gerente/operador/visualizador), mesmo formato.                                                                                                                                           │
│                                                                                                                                                                                                │
│ Ambas append-only (sem policy de UPDATE/DELETE, mesmo padrão de porta3_autorizacoes_excecao), SELECT restrito a admin.                                                                         │
